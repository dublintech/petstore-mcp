Every request from Claude Desktop starting mcp-remote to a tool call. Each value is coloured by where it is defined; a red outline means it must stay secret.

“Valid for one server”: which one?

Both, in different claims. The token names the server that made it and the server that may accept it.

iss = http://localhost:9000issued by one authorization server (petstore-auth)
aud = http://localhost:8081/mcpaccepted by one resource server (the gateway). The API would refuse it, because it isn't in aud.

Filled dot: holds the value. Red: a secret. Ring: holds only the public half or a hash.

Front channel: nothing secret

Browser URLs end up in history, logs and Referer headers. The only sensitive value there is the code, and it is useless without the verifier, single use, and expires in 5 minutes.

Back channel: the secrets

The verifier and the tokens travel only in direct requests, in bodies and headers. In production these use HTTPS; mitmweb sees them only because it sits in the middle on plain http.

The private key never moves

petstore-auth signs with it. The gateway gets only the public key from the JWKS, and checks every token locally, with no call back.
